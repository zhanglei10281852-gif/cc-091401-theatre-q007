# 领域约定

为观众安排无障碍席位、陪同票和现场辅助设备。

## 核心对象

- 场馆（venues）→ 席位分区（zones，含各入口通道最小净宽、译员可视标记）→ 席位（seats）
  - 席位类型：`wheelchair` 轮椅位、`companion` 相邻陪同席（`adjacentTo` 绑定轮椅位，每席 2 个）、
    `aisle-transfer` 过道转换席、`standard` 普通席
- 演出场次（performances）：时间、场馆、售罄标记、是否安排手语译员
- 志愿者陪同班次（shifts）：覆盖时间区间必须包含整场演出，容量按场计
- 借用设备（devices）：型号与助听器兼容特征，状态 `available` / `maintenance`
- 申请（requests）：需求输入 + 授权 scope + 锁定方案（plan）+ 履约时间线 + 结果
- 通知（notifications）：类型、受众、去重键、截止点 `dueAt`、发送状态
- 授权模板（consentTemplates）：scope 清单，敏感 scope（health.note）单独标注

## 硬约束

- 陪同人数不得超过轮椅位相邻陪同席数量（上限 2）
- 到达席位的通道最窄净宽必须 ≥ 轮椅通行包络（默认 900mm，可随申请声明个性化宽度）
- 助听设备型号必须匹配观众助听器的兼容特征，不跨类型自动替代（仅给出说明性建议）
- 手语译员每场最多服务一席；该席必须位于译员可视区域
- 志愿者班次必须时间覆盖整场且仍有容量

冲突时返回结构化 `violations`（编码 + 人话原因 + 关键实测值，如净宽毫米数）与
`alternatives`（同场次重排 / 转场其他场次 / 说明性设备建议 / 人工协调）。

## 边界

- 敏感信息按角色最小可见，且以观众授权 scope 为第二道开关；客服看不到健康自由文本与联系方式明文
- 同一席位和设备不能被并发占用：写操作串行事务化，落锁前在最新状态上重新评估
- 通知按 (申请, 类型, 去重键) 幂等；确认通知每申请一行，方案指纹不变不重发
- 取消/转场/资源故障立即释放或重排锁定；转场与变更不重置提醒的原始截止点
- 通知与状态全部持久化，重启后按原截止点继续，过期待发只补发一次

时间字段使用带偏移量的 ISO 8601 字符串，外部记录保留来源和接收时间。示例数据仅用于说明字段含义。
