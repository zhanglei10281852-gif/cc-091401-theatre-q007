# 剧院无障碍服务

为观众在售罄演出前安排**无障碍轮椅席、手语翻译、助听设备、陪同票**，并完成现场签到、
交接、异常处理与演出后的脱敏履约记录。

## 能力

- **购票后补充/变更**：申请可先于购票提交，`ticketRef` 后补；变更基于乐观锁并重排资源。
- **按场次锁定资源**：席位、陪同票、志愿者班次、设备库存在一个 IMMEDIATE 事务内
  “余量检查 → 硬约束校验 → 写分配台账”，台账部分唯一索引兜底，**并发申请不会占用
  同一席位或设备**。
- **硬约束**：陪同人数（相邻陪同席 + 每场陪同票余量）、过道净宽 vs 轮椅宽度、
  设备兼容需求（t-coil/蓝牙/字幕）、手语技能与班次。
- **隐私最小可见**：敏感健康信息（含来源与接收时间）仅对授权的现场履约角色可见，
  客服只看到服务编排所需的非敏感字段。
- **可解释替代方案**：取消、整场转场、临时资源故障时自动同场重排；排不下则给出
  转场/候补/替代服务/减少陪同的选项及原因。
- **不重复打扰**：通知以去重键唯一索引幂等；服务提醒的截止时间持久化，**重启后
  未发送提醒按原截止点继续**，转场后旧场次未发提醒自动作废。
- **现场闭环**：签到 → 逐项交接（全部完成才 `fulfilled`）→ 异常接口触发重排。
- **演出后脱敏记录**：关场生成不可逆化名记录，可按场次查询。

## 运行

需要 Node.js 22+（内置 `node:sqlite`，无第三方运行时依赖）。

```bash
npm ci
npm run seed          # 写入样例数据到 .runtime/theatre.db（可选）
npm start             # 默认 :8000
npm test              # node:test 测试套件
```

也可以 `docker compose up --build`。

接口通过 `X-Role: customer-service | fulfilment | admin` 区分角色；详见
[docs/api.md](docs/api.md)。领域约定见 [docs/domain.md](docs/domain.md)。

## 结构

```
src/
  app.js               HTTP 路由 / 角色 / 错误映射
  index.js             启动（含通知分发与优雅关闭）
  container.js         组合根
  db/                  schema（SQLite）、Store 数据访问、事务封装
  domain/              常量、硬约束规划、隐私脱敏、校验、错误
  services/            申请编排（申请/变更/取消/转场/故障/闭环）、通知分发
scripts/seed.js        场馆设施、席位布局、班次、设备、授权样例
tests/                 node:test 用例（约束、生命周期、隐私履约、通知重启、HTTP）
```
